The standard (batch) protocol imputes the WHOLE series once and reads test features from that fill (\emph{Reported}). Deployment is online: each test row is re-imputed STRICTLY point-in-time on the prefix up to that row (\emph{Live}, expanding walk-forward) -- the only number a live system could have produced. The same trained model is scored both ways, so $\Delta = $Reported$-$Live isolates the imputation look-ahead. \textbf{Two findings.} \emph{(Honesty)} the non-causal imputers (LinearInterp, SoftImpute) post strong \emph{Reported} $R^2$ that \emph{collapses} Live ($\Delta \gg 0$): their batch advantage is pure look-ahead, the imputation analogue of the leak in Bryzgalova et al., \emph{Missing Financial Data} (RFS 2025). \cafe{} (and the other causal baselines) have Reported $\equiv$ Live, $\Delta = 0$ \emph{by truncation invariance} (verified via \texttt{assert\_causal}). \emph{(Utility)} among causal methods, \cafe{}'s point-in-time cross-sectional fill gives the best deployable (Live) $R^2$ (\textbf{bold}), beating raw-NaN and LOCF because it reconstructs the missing cell from the contemporaneous cross-section. \emph{Online evaluation is the deployment-correct one: it is the only protocol that does not reward look-ahead.} \textbf{Utility finding:} across 4 panels \cafe{} has the best Live $R^2$ among causal methods in 3, loses on average 0.002 Live $R^2$ over raw-NaN and gains 0.112 over LOCF -- a real online improvement, no look-ahead.}
